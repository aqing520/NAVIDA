1. 生成 R2R 专家数据（action chunking 格式）
2. 构造 correction 修正数据（对齐专家格式），混合训练并评估

核心结论：

- correction 数据对齐 chunking 格式后训练，checkpoint-1000/4000 均严重退化
- 模型行为：第一步就 stop 或一直转圈，SR=0%
- 之前记录的 "val_seen +1.8%, val_unseen +0.5%" 实际是 base model 的结果（vLLM 加载的是 base model，不是 checkpoint）

Action Chunking 规则

原始训练数据的 label 是 action chunk，不是单个动作：
- 70% 概率合并同类型连续动作：forward 25+25=50（最大 75cm），turn 同理（最大 45deg）
- 不同类型逗号分隔，最多 3 个动作：如 "forward 50 cm, turn right 15 degree"
- chunk 内动作共享同一组历史帧，chunk 结束后才更新图像

Correction 数据（v2，action chunking 版）

错误类型：
- Type 1 (d_goal ≤ 3.0m, 没停): 76,586 个, label="stop"
- Type 2 (d_goal > 3.0m, 错误停止): 555 个, label=oracle chunk
- Type 4 (前10步与oracle不一致): 18,272 个, label=oracle chunk

与 v3 的区别：
1. 修正数据 label 从单动作改为 action chunk
2. failure 粒度从整个失败 episode 改为只取真正出错的步
3. 专家数据从 rollout 构造改为原始专家轨迹

输出: data/correction_expert/correction_train.jsonl
样本数: 95,413

混合数据与训练：

混合: 专家 270,528 (90%) + 修正 30,058 (10%) = 300,586
输出: data/correction_expert/mixed_expert_correction.jsonl
训练: 6 GPU, lr=5e-6, 1 epoch, checkpoint 每 1000 步
结果目录: result/navida_correction_v4/

Correction v4（action chunking 对齐版）

数据: 专家 90% + Type 1/2/4 修正 10% = 300,586 samples
训练: 6 GPU, lr=5e-6, 1 epoch
结果目录: result/navida_correction_v4/

评估结果:
- checkpoint-1000: SR=0%（第一步就 stop，Type 1 stop 标签过多）
- checkpoint-4000: SR=0%（一直转圈）

失败原因：Type 1 (stop label) 占 80%，模型过度学习 stop

====================================
Correction v5（参考 CorrectNAV 偏离检测）

思路：检测偏离点（model_action ≠ oracle_action），从偏离点取 oracle 纠错轨迹
数据: 46,061 samples, correction 比例 2%
训练: 6 GPU, lr=5e-6, 1 epoch, checkpoint 每 500 步
结果目录: result/navida_correctnav_v5/

评估结果 (checkpoint-500, val_seen 采样 34 episodes):
  SR: 0%    模型一直转圈，触发外部旋转限制停止

失败原因分析：
1. 训练数据第一个动作 81.6% 是 turn（left 41.5% + right 40.1%），只有 18.4% 是 forward
2. 原因：偏离检测用的是 rollout 记录的 oracle_action（从 oracle 位置算的），
   不是从偏离后 agent 实际位置算的
3. 常见场景：model 往前走了，oracle 说"该转了" → 纠错标签是 turn
   但从 agent 实际位置看，正确动作可能是继续 forward
4. 模型学到"偏离就转" → 推理时一直转 → 旋转限制触发停止

根本问题：纠错轨迹的 oracle_action 基于 oracle 位置，不是 agent 实际位置
需要：从偏离点的 agent_position 用 ShortestPathFollower 重新规划纠错轨迹
====================================



====================================
Correction v6（几何偏离检测，只取失败 episode）

思路：参考 CorrectNAV，用 agent 到 reference_path 距离 > 阈值检测偏离点
数据构造: src/data/build_correction_nav_v5.py, threshold=3.0m
只取失败 episode 的偏离点，从偏离点开始取 oracle action 构造 action chunk

数据: 专家 270,528 (99.44%) + 修正 1,531 (0.56%) = 272,059
训练: 6 GPU, lr=5e-6, 1 epoch, checkpoint 每 100 步
结果目录: result/navida_correctnav_v6/

评估结果 (checkpoint-100, val_seen 采样 22 episodes):
  SR: 9.09%    OSR: 18.18%    SPL: 5.84%
  对比 baseline 同 episode: SR 大幅下降

失败原因：学习率仍然过高，模型对修正数据过拟合
====================================



====================================
Correction v7（降低学习率到 5e-7）

与 v6 相同数据和方法，仅降低学习率
训练: 6 GPU, lr=5e-7, 1 epoch, checkpoint 每 50 步
结果目录: result/navida_correctnav_v7/

评估结果 (checkpoint-50, val_seen 采样 38 episodes):
  V7 SR: 50.00%    OSR: 63.16%    SPL: 46.60%
  Baseline SR (同 episode): 71.05%
  Delta: -21.05%

失败原因：即使 lr=5e-7，继续在专家数据上训练仍导致性能退化
根本问题：不是学习率的问题，而是从 base model 继续训专家数据会破坏已有能力
可能解法：需要完全不同训练策略（如 LoRA、只训 correction 数据、或冻结大部分参数）
